TL;DR

  • A new app/messaging context with three tables (migration 0061): conversations (ITEM / GROUP / TERM), messages and conversation_reads. There is no participant table; access is computed per request, and soft-deleted groups count for both the access checks and the inbox.
  • 9 endpoints under /api/conversations, with the literal routes declared before /{id}. ITEM threads are unique per (item, asker, current owner). A GROUP chat goes read-only when its group is deleted or switched to PUBLIC. Sends are moderated, rate-limited, serialized per conversation and never notify the bell.
  • A 💬 badge (20 s poll), InboxPage, and ThreadPage (one ["thread", …] query polling after= every 5 s and merging into the cache). Audit times are parsed with dayjs.utc(x).local(), Polish error copy comes through serverMessageOr, and the 7 binding mockups use theme tokens only.

Key Decisions

  • No participant table. Access is computed from current data.
  • ITEM uniqueness is (item, asker, owner) (user decision). After a GIVE or SWAP, a new thread opens with the new owner; the old thread stays writable for its two parties.
  • A PUBLIC group's chat is read-only (user decision). Writing reopens if the group goes back to PRIVATE. Get-or-create returns an existing chat, or 409 when there is none.
  • read_only_reason is null | GROUP_DELETED | GROUP_PUBLIC, and a deleted group takes precedence.
  • Membership and audience checks include soft-deleted groups through new repository queries. Existing helpers are untouched.
  • Send takes a FOR UPDATE lock and stamps a strictly increasing created_at, so commit order equals cursor order. after= polling never skips a message, and GREATEST cannot mark an unseen one read.
  • Real FKs for item_id, group_id and term_id, following models.md.
  • The server builds title; the client formats every time. subtitle is dropped.
  • Item imagery is a fixed 📦 placeholder, with no thumb_url.
  • "Czat terminu" is gated on the new access.is_active_attendee; is_attending is unchanged.
  • Initials-only avatars; the inbox shows chats with messages (newest 100); the badge counts messages; mark-read takes a message_id; asking about your own item returns 409.

Open Questions / Risks

  • infoLate joiners start with the whole history unread ("9+"). Accepted.
  • infoA new organizer gains the history; the previous one loses it. Accepted.
  • infoNames on public terms are already shown through guardians; the new exposure is message content.
  • infoAfter an owner change, an asker can hold two threads about the same item. Accepted.
  • infoAn old chat of a PUBLIC group is reachable only from the inbox or a deep link.
  • warningRate limits live in memory per worker, and a restart resets them.
  • warningConcurrent sends queue on the row lock. Moderation runs before the lock.
  • warningBielik adds latency and can return 503; the composer keeps the text.
  • infoGuests cannot chat and are not counted in participant_count.

Scope

Goal: let a logged-in user ask an item's owner about the item, and let PRIVATE-group members and term attendees talk with their organizer in Messenger-style threads. Unread state shows as a polled badge on the inbox button.

In scope
  • ITEM 1:1 threads (asker ↔ current permanent owner; a new thread after an owner change)
  • GROUP chat (created for PRIVATE groups only; read-only while the group is PUBLIC or deleted)
  • TERM chat (organizer and active attendees; stays open after the term)
  • Inbox, unread badge, polling (20 s / 5 s)
  • Moderation, rate limits (30 messages/min, 20 new item conversations/h)
  • Four entry points
Out of scope
  • Attachments, editing or deleting messages, typing indicators, read receipts, reactions, search
  • Block and report, email and push, bell notifications
  • New chats for PUBLIC groups, a "Moje grupy" list, leaving or muting a conversation, merging ITEM threads across owners
  • Profile photos and item thumbnails, profile links, inbox paging beyond 100, WebSocket or SSE

User Stories

As a visitor on someone else's item page, I want to tap "Zapytaj o rzecz" so that I can ask the owner without exchanging contact details first.
As an item owner, I want to see questions about my items in an inbox with an unread badge so that I can reply.
As a PRIVATE-group member, I want "Czat grupy" on a term page so that I can talk with the organizer and the other members.
As a term attendee, I want "Czat terminu" so that I can coordinate with the organizer and the other attendees.
As an organizer, I want "Czat grupy" on the group details page and "Napisz do uczestników" on the attendee list so that I can reach my people.
As any participant, I want new messages to appear without reloading, and to know when a chat has become read-only, so that I don't miss or lose anything.

Technical Approach

Layering and access
  • The router resolves the profile and calls the application layer, which commits. Repositories only read, except for the Core hot-row statements.
  • access.resolve_access returns {read_only_reason, organizer_party_id} or raises 404 / 403.
Inbox and unread in fixed queries
  • Profile → three audience statements → one conversations query (ITEM by party; GROUP by led ∪ member; TERM by attended or led; last_message_at not null) joined to my read row and an unread count → DISTINCT ON last message restricted to ≤100 ids → batched labels.
  • Unread-count is the same query as one SUM, with no LIMIT. Read-only rows are listed and counted.
Cursors and the ordering guarantee
  • before: < anchor DESC LIMIT 51, reversed. after: > anchor ASC LIMIT 51. The 51st row sets has_more.
  • Send locks the conversation row (FOR UPDATE) and stamps created_at = max(utcnow, last_message_at + 1 µs), so commit order equals cursor order. Any poll that sees M sees every earlier message.
  • The client marks only the newest message it holds, so GREATEST never covers an unseen message. A first visit to a long-unread thread marks everything read once the newest 50 are shown. Accepted.
Get-or-create race and time
  • Insert inside begin_nested(). On IntegrityError, re-select. This works under the test db_session.
  • Audit timestamps are naive UTC. occurs_on is used only for the server-built TERM title. No business rule compares against the current time.
useThread under TanStack Query
  • One useQuery with key ["thread", username, id], refetchInterval 5000 and no background polling.
  • queryFn: with an empty or missing cache, fetch the newest page; otherwise fetch after=<last id>, then re-read the cache and merge (dedupe by id, sort by (created_at, id)).
  • loadOlder and send are callbacks that call setQueryData. markRead invalidates the unread and inbox queries. There is no effect-based fetching and no useInfiniteQuery.

Success Criteria

  1. The migration round trip passes, with the indexes and FKs present.
  2. ITEM: 201 then 200; owner 409; permanent owner; a new id after a GIVE while the old thread still works.
  3. Access per kind; 404 comes before 403.
  4. Read-only: a deleted group (members and organizer) gives GROUP_DELETED; a PUBLIC toggle gives GROUP_PUBLIC and is reversible; a deleted item stays writable.
  5. Validation and moderation: Polish 400 with no fieldErrors; nothing written on rejection.
  6. Rate limits: the 31st send and the 21st new conversation return 429; a re-open returns 200.
  7. Read markers: the count is exact and uncapped; GREATEST; own messages never count.
  8. Query budget: equal counts for 3 vs 9 conversations, for both the inbox and unread-count.
  9. Paging and ordering: 50 per page with has_more; strictly increasing created_at.
  10. /unread-count returns 200, not 400.
  11. No bell rows.
  12. Polling uses one thread query whose after= poll merges into the cache.
  13. Time display: naive UTC 10:00 renders as 12:00 in Warsaw (CEST); the pinned formats hold.
  14. The view-state table is complete.
  15. The entry-point matrix holds, including the withdrawn attendee and the anonymous visitor.
  16. Mockup fidelity, including the read-only header line and the banners.
  17. Quality gates pass: ruff, mypy, tsc, eslint, the new tests, themeTokenUsage and PublicLayout.test.
