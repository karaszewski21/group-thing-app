TL;DR

  • The public event page moves to /<organizer-slug>/event/<eventId> in Term styling. The old /events/:eventId page route is removed with no redirect.
  • app/events gains attendance sign-up and withdraw, a batched participants+items read model, author_slug on every response, GET /api/events/attending and an OG preview. It reads other business contexts only through new *_acl.py modules; organization lookups are batched. Spec-audit decisions and fixes are applied (see Audit amendments).
  • Messaging gains an EVENT kind. Migration 0071 adds conversations.event_id with ON DELETE CASCADE, makes the messages/reads FKs cascade, and adds a partial unique index.
  • On the frontend, event-only components go in pages/events/components/ (Term components are not modified), alongside a discriminated resolveEventView with isStale (the token is kept out of the query key), EVENT branches in Inbox/Thread, and attended events in Spotkania.

Open Questions / Risks

  • infoAn expired token on sign-up takes the anonymous branch (400 "Podaj swoje imię." without a name), as in Term RSVP. Accepted and documented (L9).
  • infoOld /events/<id> links hit React Router's default error page, because there is no catch-all or errorElement.
  • criticalMessaging blast radius: if any kind switch lacks an EVENT branch, the inbox breaks. The mixed-kind inbox test is the guard.
  • warningAnonymous sign-ups stay unthrottled. Only the name is moderated.
  • infoWithdraw stays possible after the end but is hidden in the UI. An ended event with attendees can't be deleted.

Scope

In scope
  • The slug route /:organizationSlug/event/:eventId, always public
  • Sign-up for logged-in users and guests; withdraw for logged-in users
  • Participants and their AVAILABLE items, read-only; the author first as "Organizator"
  • EVENT chat, cascaded on delete
  • OG preview; author_slug everywhere; attended events in Spotkania
  • Guest merge via AccountMergeForm
Out of scope
  • Take/swap; capacity; needed items; group visualization; embedded chat
  • A short public code; a redirect from /events/:id; a catch-all 404
  • The author removing participants; guest withdraw; moving edit under the slug
  • Parametrizing Term components (except the AccountMergeForm copy props)
  • Rate-limiting anonymous sign-ups; clearing the guest key after a merge; an event link in the thread header

User Stories

Anonymous visitor
As an anonymous visitor with the link, I want to see the event, who is coming and what they share, and to sign up as a guest with only my name.
Guest
As a guest who has signed up, I want to turn my guest profile into an account in place, so that I can chat and withdraw.
Logged-in user
As a logged-in user, I want to sign up with one click, see myself marked "To Ty", open the event chat, and withdraw if my plans change.
Author
As the event author, I want to share a link that has a rich preview, see participants and their items, chat with attendees, and edit or delete the event.
Participant
As a participant, I want events I signed up for to show in Spotkania → "Biorę udział".

Technical Approach

Schemas and exact response keys
  • EventResponse: id, name, description, starts_at, ends_at, location, created_at, updated_at, author_slug
  • EventDetailResponse adds: banner_url, attendee_count, is_author, author_display_name, organization{name, primary_color, accent_color, palette_preset}|null, participants[], is_attending, has_ended
  • EventParticipantResponse: party_id, display_name, is_author, is_me, items[{item_id, product_name, mode, thumb_url}]. The author comes first, then attendees in sign-up order. Items are AVAILABLE only, ordered by name (C collation) and then id.
  • EventAttendanceRequest (extra=forbid): guest_name|null · EventAttendanceResponse: id, event_id, user_profile_id, attached_to_account
Service functions, ACLs and routes
  • sign_up checks, in order: 404 (event loaded FOR SHARE so a racing delete gives 404, not 500; L3) → 409 ended ("Wydarzenie się zakończyło.") → logged-in: 409 author ("Organizator nie zapisuje się na własne wydarzenie."), return the existing row or insert in a savepoint and re-select on IntegrityError → anonymous: 400 name ("Podaj swoje imię." / "Imię może mieć najwyżej 255 znaków."), check_text, guest profile, insert.
  • withdraw: 404, then the caller's profile (401 without one), then sets withdrawn_at. Idempotent 204.
  • list_attending_events; resolve_author_slugs (one batched get_own_organizations_by_party_ids statement; M5); messaging-support functions; get_event_preview.
  • page.get_event_page loads: event, banner, location, viewer, organization, attendances, names (one IN query), items (one join), thumbnails (one query). Constant query count.
  • ACLs (business contexts only; platform modules stay direct): users, the "guest identity" facade (find_caller_profile, list_display_names, create_guest_profile, AVATAR_UPLOAD_DISABLED_MESSAGE), organizations (single and batched), groups (item_listing_preferences_select, derive_party_slug), circulation (available_items_select), product (first_approved_photo_by_product).
  • Routes: GET /attending (declared before /{id}), GET /{id}, POST /{id}/attendances 201, POST /{id}/attendances/withdraw 204.
Authorization matrix order (events block)
  1. GET ^/api/events/(mine|attending)$ → READ, mcp:read
  2. GET ^/api/events/[^/]+$ → PUBLIC
  3. POST ^/api/events/[^/]+/attendances$ → PUBLIC
  4. POST ^/api/events/[^/]+/attendances/withdraw$ → EDIT, mcp:edit
  5. The existing PATCH/DELETE, create and banner rows. /api/conversations/event is covered by row 54; the OG route by row 10.

OG preview

GET /{organization_slug}/event/{event_id} sits before /{organization_slug}. Reserved or dotted first segments are delegated to spa_fallback (L10). An invalid UUID or an unknown event returns the plain index. The tags are: title = event name; description = format_term_when plus the place and description; og:image = the banner w1600.

Success Criteria

  • All 7 binding screens render with their copy and order; /events/<id> no longer matches a page route.
  • Guest, merge, logged-in sign-up and withdraw work end-to-end. Sign-up after the end returns 409, and the author can't sign up.
  • The detail endpoint's query count is constant, asserted with count_queries.
  • EVENT chat access is correct, it appears in the inbox and unread count, and deleting the event cascades the conversation, messages and reads.
  • 0071 upgrades and downgrades cleanly; author_slug is on every event response and in every link; the OG preview works; Spotkania lists attended events.
  • The Term page and its tests are unchanged and pass; new tests, mypy/ruff (baseline) and tsc are green.
