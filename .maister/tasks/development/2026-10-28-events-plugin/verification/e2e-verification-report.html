TL;DR

  • NO-GO. GET /api/plugins returns extension_points, but the host reads plugin.extensionPoints, so /add/event always shows the fallback. The bug predates the task, but it makes the feature unreachable.
  • With a test-only route shim, the plugin, done and uploadImage work end to end. 9/10 scenarios passed (4 with issues).
  • iframe chrome is 246 px on phones; recommended FRAME_STYLE = { height: "calc(100dvh - 250px)", minHeight: "400px" }.

Key Decisions

  • The test continued past C1 by rewriting the /api/plugins response in Playwright. No code was changed.
  • Storage was disabled (409 mode), so scenario B covered the banner-failed path, not the thumbnail path.

Open Questions / Risks

  • critical The key-shape mismatch likely breaks every plugin extension point, admin pages included. Unit tests stub camelCase fixtures, so they do not catch it.
  • A duplicate dev registration Events (same manifest) is also enabled, and the host picks it.
  • The banner success path (APPROVED row + WebP files) was not verified at runtime.
