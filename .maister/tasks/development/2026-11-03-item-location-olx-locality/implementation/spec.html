TL;DR

  • A place becomes Lokalizacja (a required TERYT locality from our own dictionary, by name or postal code) plus an optional Adres (Google or typed). name and notes are dropped, and responses carry a computed label.
  • Every item gets its own required location_id: set on create, editable on edit, cleared on GIFT/SWAP, and required to list a draft item. It replaces the removed inventories.location_id.
  • The item's own location block shows everyone the locality only; only the owner gets the address. Term/event context lines keep the full label, because those addresses are already public.
  • Every picker uses page mode, and both legs of the /places/new trip replace the history entry. Drafts live in AppDataContext with defined clear points.
  • Migrations: 0078 (tables), 0079 (chunked unnest seed) and 0080 (rework), all with plain downgrades.

Goal & Scope

Make every item carry a required, owner-chosen place, shown publicly as an OLX-style locality. Reduce the place form to "Lokalizacja" (TERYT, name or postal code) plus an optional "Adres", used consistently through one page-mode picker.

In scope

  • Locality dictionary (TERYT SIMC/TERC + GUGiK postal) with build script, fixture and seed
  • GET /api/localities search
  • Places reworked: locality + optional address, computed label, PUT, no dedup
  • Required per-item location: create, edit, transfer clear, DRAFT → ACTIVE guard
  • Item location privacy (locality public, address owner-only)
  • Pickup reads the item location; inventory location removed
  • Page-mode pickers everywhere with history-replacing round trip and AppDataContext drafts
  • About 15 display sites updated

Out of scope

  • Locality on item cards and lists
  • City districts and locality parts
  • Coordinates for locality-only places; distance or area search; filtering by locality
  • A server-side Google vs TERYT consistency check
  • Notifying the other party of a location change during an open personal pickup
  • A warning or cascade when deleting a place used by listed items
  • Truncating long location_name in OwnerMeetingsPage/ChooseContextSheet
  • mypy on scripts/ (ruff only)
  • Legacy data migration; automated dictionary refresh
  • Changing place optionality on terms, events and groups

User Stories

As an item owner, I want to choose where my item is when I add it, so buyers know the town without seeing my address.
As an item owner, I want to add a new place with + without losing the name, category, description and photos I entered.
As the owner of a received item, I want to set my own location before offering it again.
As a buyer (logged in or anonymous), I want to see the item's town with gmina/powiat/województwo and open it in Maps.
As a user adding a place, I want to find my village by name or postal code, and add an exact address only when needed.
As an organizer, I want the term/event place picker to work the same way, with my form kept intact.

Technical Approach

Data flow
  1. LocalityCombobox calls /api/localities; the address field calls Google client-side.
  2. LocationAddForm calls POST/PUT /api/locations, re-read via load_location.
  3. The pickers hand the place id to their hosts.
  4. Item POST/PATCH stores location_id after the ACL check.
  5. /actions and pickup read the item's location; the ledger clears it on GIFT/SWAP; DRAFT → ACTIVE requires it to be live.
Migrations 0078 / 0079 / 0080 and seed cost
  • 0078: localities (pk, text_pattern_ops index, kind CHECK) and locality_postal_codes (pk, CASCADE FK, varchar_pattern_ops index). Downgrade drops both.
  • 0079: streams the gzipped CSVs and validates them; one INSERT … SELECT * FROM unnest(bound arrays) per 10k-row chunk; logs counts and time. Downgrade: TRUNCATE.
  • Seed cost: ≤3 s target, 10 s ceiling. All 22 migration tests cross 0079, and no skip is possible (0078's downgrade drops the tables). The runtime is measured; above a 2-minute overhead, 0079 switches to asyncpg copy_records_to_table via driver_connection + await_only.
  • 0080 up: lock_timeout → null the 4 FKs + DELETE FROM locations → locality_id, drop name/notes, nullable address/source, CHECK, drop the unique index → item location_id + FK + index → drop inventories.location_id.
  • 0080 down: the reverse; lossy and plain. The docstring and runbook say all places and item locations are deleted.
Locations module, item reads and writes, frontend state, docs
  • Loaders use joinedload + populate_existing and include soft-deleted rows. POST/PUT and get_own_location use them, the ACLs delegate to them, and the label builder reads the loaded locality.
  • Circulation resolves the party via find_party_id_by_user_id before get_owned_location. item_actions uses item.location_id, and _viewer_location returns the locality only for non-owners. The /details location_id uses the pickup's live check.
  • The new AppDataContext slices follow the eventDraft/eventEdit shape with Req. 30 clear points; photos stay in-memory File[]; the facade is unchanged.
  • Docs: architecture.md (dictionary, item location, guard scope, runbook), models.md (carve-out, loaders and post-write reload), migrations.md (CSV + unnest, TRUNCATE downgrade), INDEX.md.
