TL;DR

19 task groups (10 backend, 7 frontend, 1 docs, 1 test review), 117 steps, about 91–125 focused tests. The backend builds outward from two independent roots (config/clock and the 0110–0112 data layer) to the email core (rules, links, rendering, senders), then enqueue, send job, webhook, preferences/unsubscribe and account tokens, and ends with app wiring (lifespan, job, matrix, guards). The frontend starts from two independent roots (API/hooks and routing plumbing), then builds four page groups and a final route/SSR fixture group. Docs and the runbook follow once backend and frontend are done, and the Test Review group closes the plan. No step commits: all work stays uncommitted.

Key Decisions

  • The spec's 11 test groups are re-cut into implementation groups so that no group exceeds 8 tests and no two unordered groups share a file. Webhook and preferences/unsubscribe are separate groups (serialised on app/email/router.py), and profile exposure is split from account tokens (serialised on users/service.py).
  • app/main.py is edited by exactly two groups, in order. Group 7 includes email_router (so the webhook tests can reach it through client), and group 10 adds the lifespan checks, the sender wiring and the _run_email_send schedule.
  • tests/conftest.py is edited by group 1 (both email flags forced to false) and group 3 (the fake_email_sender fixture, which needs the sender types).
  • All matrix rows, the boundary/clock guard tests and test_authorization_matrix.py live in one group (10), because the matrix is a reference table checked by tests, not a runtime gate. Routes enforce through Depends(require_any(...)) from the group that writes them.
  • The frontend groups code against the spec's HTTP contract, so they do not depend on the backend groups and can run alongside them.
  • The MyProfileResponse type change (group 11) owns every typed test fixture that tsc flags for the missing email_verified, including ssrSafety.test.tsx. Group 17 later adds that file's page cases.
  • Backend organizations/slugs.py and frontend reservedSlugs.ts change in the same group (12), because the spec requires them "together" and a parity test covers both.
  • The last group is test review, not a commit or push step. Verification and finalization belong to the calling workflow.

Open Questions / Risks

  • risk.maister/docs/project/architecture.md already has uncommitted edits in the working tree (git status). Group 18 must edit it in place and keep those edits.
  • riskThe hook sits on the shared bell path (notifications/service.py). A failure there breaks every notifying write path. Group 5 must keep test_notifications.py, test_wants_notifications.py (pins at l.92/l.115 unchanged with flags off), test_term_end_scan.py and test_points_purchase_flow.py green.
  • riskMyProfileResponse touches about 12 frontend test fixtures. Group 11 has to fix every one that npm run typecheck flags, or later groups inherit typecheck noise.
  • riskBaseline noise: 32 vitest, 2 stale backend tests, mypy 15, ruff 64. Every group compares against this baseline, not against zero.
  • riskThe task system (TaskCreate/TaskUpdate) was not available to the planner. Group-level task items were not created, so the markdown checkboxes are the only progress tracker.
  • riskCopy that is not in the mockups (BOUNCE text, the scope=all done text, loading/error copy, the „wkrótce” note) is proposed in the spec and still needs a product read. It is implemented exactly as the spec gives it.
Every group: never print secret values (no env/printenv/docker inspect/cat .env; names and presence checks only) · no git commits · compare against baseline (32 vitest, 2 stale backend, mypy 15, ruff 64).
