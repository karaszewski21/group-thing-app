Open Questions / Risks

  • Owner identity is public (W2). Anonymous visitors see the item owner's display_name and party_id through /api/items/{id}/actions and /api/groups/public/parties/{id}/items, plus the owner's nearest date. This covers people who are not Organizations. Someone has to decide whether that is acceptable.
  • Lock released mid-flow (W1). The event FOR SHARE lock does not hold through take/propose/accept, because create_reservation and confirm_reservation commit inside the flow. A delete_event running at the same time can produce a 500 StaleDataError or leave a PROPOSED proposal that can never be resolved.
  • Rollback is forward-only once event reservations exist. Rolling back after that point means following the 0073 runbook: purge the event rows manually or restore the dump.
  • New files are untracked. All new files, including migration 0073, are still untracked in git and must be committed together.
  • Pre-existing test failures overlap this work. The 13 failing frontend tests cover pending actions and the term page, which this task touched, so they could hide a regression there.
