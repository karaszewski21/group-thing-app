TL;DR

  • The Facebook/Google mock in SocialAuthButtons becomes one real Google button, rendered by Google Identity Services (GIS) on /login and on the six AuthSheet surfaces. The ID token carries a server nonce issued by POST /api/auth/google/nonce and held in a signed HttpOnly cookie; the 9-minute refresh pauses while the tab is hidden or a sign-in is in flight.
  • POST /api/auth/google verifies the token locally (pyjwt[crypto] + Google JWKS, cached per verifier instance). It logs in the linked user_identities row or creates a GUEST account through the shared bootstrap_person_account, and returns {token, created, party_id}.
  • An email already registered (compared case-insensitively) gets a Polish 409, with no merge. An unverified email gets a 403. An unclassified insert conflict is retried once, then gets the generic Polish 401; register gets the same retry.
  • Migrations 0107 (user_identities) and 0108 (nullable password_hash, guarded downgrade) ship with a runbook. The feature is off unless the client ID is set on both stacks.

Key Decisions

  • Config: GOOGLE_CLIENT_ID, AUTH_COOKIE_SECURE (default true), NEXT_PUBLIC_GOOGLE_CLIENT_ID. Both client IDs hold the same Web client ID. Secure is never derived from headers.
  • Nonce route is a POST (owner, M7): POST /api/auth/google/nonce with a required empty JSON body {}, so a cross-site form cannot overwrite the cookie and no GET has a side effect.
  • Nonce cookie aj_google_nonce: HttpOnly, Lax, Path=/api/auth/google, 600 s. Its value is an HS256 JWT {nonce, iat, exp, aud:"aj:google-nonce"} signed with HMAC-SHA256(JWT_SECRET bytes, "aj google-nonce cookie v1"). delete_cookie repeats Path, Secure, HttpOnly and SameSite.
  • Nonce is token_urlsafe(32). The claim must be a str and is compared with compare_digest over UTF-8 bytes. The cookie is cleared on every response the route builds (200/201/401/403/409/503), not on the central handlers' 400/500 (accepted). Not single-use (accepted).
  • Verifier is a GoogleTokenVerifier(client_id, fetch_jwks, clock); the JWKS cache, its lock, the expiry and the last-fetch time are instance state, and get_google_verifier() returns one process-wide instance. Async httpx JWKS, a 1 h cache, a forced refresh on an unknown kid (at most once every 60 s), RS256 only, both iss forms, aud/azp equal to the client ID, 30 s leeway, email_verified only when it is True.
  • Case-insensitive email (M1): is_email_registered compares func.lower(UserProfile.email) == normalize_email(email) in every pre-check and re-read, for Google and register.
  • Races (owner, M2): savepoint and re-read — identity found → log in; email taken → 409; anything else (e.g. a uq_users_username collision) retries the bootstrap once with a fresh username. A second failure → generic Polish 401 (cookie cleared). Register: same retry, second failure → DuplicateEmailException (Polish 409).
  • Error envelopes are built in the route (like login's 401), so the cookie-clearing header goes on every outcome the route produces.
  • Display name: the Google name goes through check_text(PROFILE_NAME), falling back to the email-derived name.
  • Password-login NULL guard lives in the router. verify_password stays strict for OAuth2 client secrets.
  • Matrix rows 72 (POST nonce) and 73 (POST google) are PUBLIC, placed after row 47, with a comment naming them auth-flow routes.
  • Frontend: the googleIdentity.ts loader, the useGoogleSignIn hook, and loginWithGoogle throwing ApiError. The UI shows the backend message only when it equals the known Google copy for 401/403/409/503, else the generic copy. The nonce POST is imperative (a recorded data-fetching exception).
  • Refresh pause (owner, M3): the 9-minute refresh is skipped while the tab is hidden or a popup/POST is in flight and runs on return if stale; a second tab mid-sign-in is an accepted risk.
  • The Facebook mock, GoogleMark and FacebookMark are removed.

Open Questions / Risks

  • warningPopup blocking in in-app browsers has not been measured (D6 is deferred).
  • infoThe GIS iframe in the focus-trapped AuthSheet at 375 px needs a manual check.
  • infoThe 409 creates friction for password users until D1.
  • warningAccepted: one nonce cookie per browser — a second tab mounting the button mid-sign-in overwrites it; the first tab gets the generic 401 and a second click recovers.
  • infoAccepted: the nonce is not single-use; a captured (cookie, token) pair replays until the earlier of the cookie exp (≤ 10 min) and the token exp.
  • infoAccepted: the 400 and 500 from the central handlers do not clear the cookie (stateless, ≤ 10 min).
  • infoAccepted: JWTs cannot be revoked (1 h); a Google-only account has no recovery path.
  • warningThere is no image-only rollback past 0108 once Google accounts exist; in compose an old image fails to start (alembic upgrade head cannot locate 0108).
  • infoSafari over http needs AUTH_COOKIE_SECURE=false.
  • infoD14 production prerequisites (domain, privacy policy, brand) are outside the code.
  • infoAssumptions: the cookie name, the empty {} nonce body, the 60 s refresh throttle, the fixed 1 h JWKS TTL, the 5 s timeout, the 4096-character credential cap, rows 72/73, the nonce refresh at 9 min, and document.hasFocus() === false as the popup signal.

User Stories

An anonymous visitor on an AuthSheet surface signs up with Google and stays on the page.
A returning Google user signs in on /login and lands on returnTo, including OAuth2 consent.
An existing password user gets a clear Polish message to use their password; their account cannot be taken over.
A Google-created admin keeps their DB permissions (ADMIN) in the token.
An operator sees the feature stay inert until the client ID is configured.

Technical Approach

Backend module layout
  • app/config.py: google_client_id, auth_cookie_secure, google_login_configured.
  • app/auth/models.py: nullable password_hash, IdentityProvider, UserIdentity.
  • app/auth/google.py: nonce helpers and cookie, GoogleClaims, GoogleTokenInvalid, GoogleKeysUnavailable, GoogleTokenVerifier(client_id, fetch_jwks, clock), fetch_google_jwks, get_google_verifier (one process-wide instance).
  • app/auth/service.py: load_permissions, sign_in_with_google, GoogleEmailTaken, GoogleEmailUnverified, GoogleSignInFailed, and the moderated display name with its fallback.
  • app/auth/router.py: login (NULL guard), POST /google/nonce (empty body model), POST /google.
  • app/users/service.py: optional password, is_email_registered (case-insensitive), derive_display_name, bootstrap_person_account, the register refactor. app/users/router.py: load_permissions.
POST flow and error mapping

Gate (503) → cookie read (401) → verify (401/503) → sign_in_with_google. The new-account path runs the moderated name first, then the savepoint (bootstrap + identity + flush) and the commit; on IntegrityError a re-read (identity → 200, email → 409), else one retry with a fresh username, else GoogleSignInFailed → 401. Then load_permissions → encode_login_token → 200/201. The route maps the typed exceptions (and StaleDataError → 401) to ErrorResponse JSON; every outcome it builds carries delete_cookie with the full attribute set. The 400 and unexpected 500 from the central handlers do not clear the cookie (accepted).

JWKS cache and security notes
  • Instance state of the verifier: a dict kid → PyJWK, the expiry (1 h), the last-fetch time and an asyncio.Lock, timed by the injected clock. A kid missing from the keys forces one refresh if the last fetch is older than 60 s. The fetch result is validated and non-RS256 keys are skipped.
  • SameSite=Lax plus a required JSON body on both POSTs; the nonce binds the token to the browser; the purpose-keyed cookie cannot be forged; no auto-linking; the credential is never stored or logged (one INFO reason line, no email, nonce or token). The nonce is not single-use: replay window ≤ the earlier of the cookie exp (10 min) and the token exp (accepted).
Frontend flow

useGoogleSignIn(tab): configured? → getGoogleNonce() → loadGoogleIdentity() → initialize({client_id, nonce, callback, ux_mode:"popup", auto_select:false}) → renderButton(slot, {standard, outline, pill, large, logo_alignment:left, locale:"pl", text: signin_with|signup_with, width: clamp(200–400)}). It returns {status: hidden|loading|ready, slotRef, error}. A failure re-fetches the nonce and re-initializes (no automatic POST retry). A 9-minute timer refreshes the nonce, but only marks it stale while visibilityState is hidden, a POST is in flight or document.hasFocus() is false (popup open); visibilitychange/focus then refresh a stale nonce. The alert shows message only for the known Google copies. Only one live instance per page. session.ts, proxy.ts, AuthGuard, AuthSheet, LoginForm, RegisterForm and the OAuth2 server are unchanged.

Success Criteria

  1. A first sign-in creates exactly one user (NULL hash), one identity, a profile, a role and a family → 201. A repeat → 200 with the same username. Identity and username races give no 500, no English message and no duplicate rows.
  2. Every failed token or cookie check → the generic Polish 401 (table tests, no network); malformed nonce claims never raise.
  3. No email collision creates an identity, whatever the stored case: 409 for a matching email, 403 for an unverified one.
  4. Google tokens carry the DB permissions and work for /api/people/me and OAuth2 consent.
  5. Login and register contracts are kept; a NULL hash → 401; a duplicate race → Polish 409 instead of today's English 409 "Data integrity violation".
  6. No client ID → no script, button or divider; no backend ID → 503 on both routes and the block hidden.
  7. The 0107/0108 round trip and the refusal tests pass; the runbook is documented.
  8. The UI matches the seven binding mockups; the reserved status line keeps the form in place.
  9. npm run typecheck stays at 0 failures.
