TL;DR

  • Six decision areas and 23 alternatives were explored. The settled frame was not re-opened: Option A, the model in the API process on VPS A, the asyncpg-only matcher, and lexical tiers unchanged.
  • Recommended:
    • A synchronous best-effort vector write with an outbox retry, plus a reconciliation sweep for backfill.
    • A separate SIMILAR tier: born seen, capped at 10, run last, never upgraded.
    • Name-only input with the asymmetric prefix; name + leaf category is scored as the challenger.
    • Revisions 0100_pgvector + 0101_want_similar.
    • A new UI section „Powiązane rzeczy”.
  • Rollout: an offline gate on one ≥300-pair sample shared with the lexical gate, then shadow mode in which the frontend ships later. No feature switch is needed; a read-side hold is the fallback.
  • Confidence: medium. High for architecture and storage; low for real-name quality until the sample is scored.

Key Decisions

  • Writer DA1-A. Only this closes both timing holes (the window's changed_at and the one-off forward run) without routine window re-entry. Synthesis C-2.
  • Tier DA2-A. Consistent with SUGGESTION. A re-tier would only be needed after an in-place rename. Synthesis C-6.
  • Input DA3-A. Name + category (DA3-B) is adopted only if it wins on held-out precision.
  • Rollout DA4-C. A switch-free shadow keeps the 0099 gate wording; DA4-A is the fallback.
  • Migrations DA5-A. The image switch stays a standalone infrastructure deploy.
  • UI DA6-A. The existing „Podobne rzeczy — …” subtitle stays as it is.
  • Trade-off accepted: +25–50 ms (estimated) per product-creating or want-writing request, and two writer paths.

Open Questions / Risks

  • criticalQuality is unproven (hard-negative AUC 0.50–0.73). A no-go on the sample drops the tier.
  • warningDA4-C assumes the web image can be deployed on its own. If it cannot, fall back to DA4-A with an explicit gate exception.
  • warningVPS A capacity is unmeasured (R9). It drives the writer's latency budget and the +126 MB RSS.
  • infoThe lexical-anchor gate (DA2-D) loses pure synonym pairs. Score it, but do not adopt it by default.
  • infoOld-image compatibility after 0101 is inferred, not tested.

Recommended approach

DA1-A (+ DA1-D for backfill and model changes) · DA2-A · DA3-A (DA3-B and DA2-D scored as variants) · DA4-C (DA4-A fallback) · DA5-A · DA6-A

This combination closes the timing risk, the decisive integration risk. It leaves lexical tiers, bells and counts untouched, and reuses established patterns: the Bielik ONNX path, the born-seen capped tier, the 0086 extension revision and the shared visibility fragment. Quality is handled by one ≥300-pair sample that also serves the lexical gate, plus a switch-free shadow period.

  1. Writer. Sync embed in the same transaction. On error, commit and stage embeddings.requested, with a re-trigger. A throttled sweep does the backfill and model switches.
  2. Tier. SIMILAR, SEMANTIC_SIMILARITY_MIN, cap 10, run last, seen_at = $1, DO NOTHING. Constants in rules.py only, with a drift test.
  3. Input. Name only; zapytanie: on the want. The tuple (model, revision, int8, prefix, template) is pinned.
  4. Rollout. Offline gate, then image + 0100, then 0101 + backend + matcher with the web image held back for 2–4 weeks, then the web deploy.
  5. Migrations. 0100_pgvector, 0101_want_similar; downgrade 0101 → 0100 → image.
  6. UI. „Powiązane rzeczy” (final wording with the product owner).
Trade-offs acceptedAssumptions (if wrong → change)
  • +25–50 ms (estimated) per write; inference inside the transaction
  • Two writer paths plus a sweep loop
  • No instant hide after launch (only EMBEDDINGS_ENABLED off, or a web rollback)
  • The rename edge case keeps SIMILAR (no bell)
  • A third section on mobile
  • VPS A can absorb +126 MB and 25–50 ms. If not: DA1-C or e5-small.
  • The sample reaches a Wilson lower bound ≥ 0.80 with recall gain ≥ X. If not: challenger, template B or the anchor gate, else drop the tier.
  • The web image can be deployed alone. If not: DA4-A.
  • Old images tolerate a DB at 0101 (inferred). If not: the runbook forbids image-only rollback.
  • R12 backfill bells are negligible. If not: backfill before the semantic statements.

Confidence: medium. High for storage, migrations and tier shape; medium for writer and rollout mechanics; low for real-name quality.

Why not the others
  • DA1-B makes R12 extra lexical bells routine and doubles window entries. It stays as the fallback path inside A.
  • DA1-C contradicts the settled API-process decision without measured need. It is the escalation if VPS A fails.
  • DA1-D alone adds sweep lag on the happy path. It is used only for backfill and model changes.
  • DA2-B changes lexical statements and adds a bell path for a rename-only edge case that SUGGESTION already accepts.
  • DA2-C mixes meanings under a subtitle that becomes false and needs score fusion.
  • DA2-D removes the pure-synonym pairs the feature exists for. It is a scored variant only.
  • DA3-C adds an extra re-embed trigger and noise in narrow bands, with no evidence of benefit.
  • DA3-D embeds commentary the lexical tiers ignore, with a re-embed on note edits.
  • DA4-A is the fallback. It is second only because it bends "no feature switch".
  • DA4-B skips every production-only signal and exposes users first.
  • DA4-D is a heavier switch than A, with a biased sample.
  • DA5-B loses the standalone infrastructure deploy and mixes a superuser drop into a feature downgrade.
  • DA5-C solves a least-privilege problem the project does not have (F7).
  • DA6-B overpromises and churns shipped copy.
  • DA6-C needs score fusion and makes the subtitle false.
  • DA6-D means a disappearing section and an extra view-state rule.
