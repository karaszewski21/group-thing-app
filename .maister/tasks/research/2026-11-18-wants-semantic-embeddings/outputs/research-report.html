TL;DR

  • It can be built, and it is cheap; whether it is good enough is not proven yet. Run sdadas/mmlw-roberta-base as int8 ONNX in the API process. Store halfvec vectors in side tables keyed by product and want, and search them by exact scan with no vector index. Add a third tier with no bell and a cap of 10, run after MATCH and SUGGESTION.
  • Cost on VPS A (estimated): about +126 MB RAM, 25–50 ms of CPU per new name, about +1–1.7 s per capped window run (the lexical part takes about 13 s today), about +60–130 ms per forward match, and a backfill of minutes.
  • Main risk: quality. Every small model rates accessories and related items almost as high as true matches (hard-negative AUC 0.50–0.73). Embeddings therefore show related things and never ring a bell. Ship only after a labelled sample of at least 300 pairs and a shadow-mode period.

Key Decisions

  • Model: mmlw-roberta-base, int8. PKOBP/embed-modernbert-68m is the challenger scored on the same sample, and multilingual-e5-small is the lighter fallback. Reason: it has the best Polish STS score among models up to 300M, and it is the same encoder family as Bielik-Guard, which already runs on VPS A.
  • Storage: halfvec(n) with no HNSW index, compared by exact scan inside the existing SQL filters. Reason: 768-d vector was 50× slower because of TOAST, and HNSW returned 0 of 20 rows under a selective filter.
  • Writer: the API process, synchronously and best-effort, with an outbox retry that wakes the matcher again. Reason: there is no separate worker, and a vector that arrives late is missed by the window and by the one-off forward match.
  • Image and migrations: pin pgvector/pgvector:0.8.7-pg18-trixie. Add two new revisions, 0100 for the extension and 0101 for the schema, and do not amend 0099 again. Reason: the bare pg18 tag is bookworm, so its glibc differs from the existing data directory, and a third amendment would create a third shape of 0099.
  • Release: extend the release gate to at least 300 labelled pairs, scored for both the lexical rule and the semantic tier. Run 2–4 weeks in shadow mode before showing the tier.

Open Questions / Risks

  • VPS A's CPU and RAM are not documented. Every VPS figure here is a laptop or dev-host measurement scaled by an assumed factor of 1.5–3×. Measure on VPS A first.
  • The tier name „Podobne rzeczy” clashes with the existing subtitle of the suggestions section („Podobne rzeczy — brakuje im jednego słowa…”).
  • Shadow mode needs a hold on the read side, which bends the release gate's "no feature switch" wording.
  • After the rollout, rolling back to the old Postgres image cannot be done by swapping images alone. It needs downgrades and a superuser DROP EXTENSION.

Answer 2: Threshold procedure and embedding input High method / Medium numbers

Procedure

  1. Corpus: polish_names.py plus real product names plus 30–50 hand-written synonym pairs.
  2. At least 300 pairs with at least 120 independent positives. Strata: 40% positives, 30% hard negatives, 20% same-category negatives, 10% lexical-only.
  3. Labels match / related / no; two labellers; kappa on an overlap of at least 50 pairs.
  4. Score offline with the deployed int8 export, prefix and template; tune/held-out split 2:1.
  5. Compare models by average precision. Sweep T_sem in 0.005 steps and take the lowest value with precision ≥ 0.85.
  6. Go if, on held-out data, the Wilson lower bound is ≥ 0.80, hard-negative FP ≤ 10%, and recall gain over lexical ≥ X.
  7. Pin the constants in rules.py and add a drift test. Then shadow mode, then open/take rates per score band.

Wilson 95% intervals (why ≥300 and not 200)

Input

  • Default: the name only. Alternatives to score: name + leaf category, and + the first 200 characters of the description.
  • No fold_pl() before embedding; keep sizes and numbers in the text.
  • Prefixes per model are part of the threshold tuple.
  • No RRF or score fusion when deciding tiers.

Recommended rollout

  1. Offline gate: labelled sample, model and template, T_sem, go/no-go. Measure probe.py on VPS A.
  2. Infrastructure: pg_dump, image swap to 0.8.7-pg18-trixie, verify glibc and collations, upgrade to 0100, check \dx vector.
  3. Writers: 0101 plus the embedder (EMBEDDINGS_ENABLED), then a throttled backfill.
  4. Matcher in shadow: SIMILAR pairs stored born seen, API and UI held back for 2–4 weeks.
  5. Shadow metrics: pairs per want, score histogram, overlap with lexical (should be 0), 100-pair spot check (≥ 0.80), window time and capped=, forward p95, embed p95 and timeouts, RSS, FAILED outbox rows, listings and wants without a vector.
  6. Show the tier; track open and take rates per score band.
  7. Optional bell only if precision on match has a Wilson lower bound ≥ 0.90.

Key insights

High

“Related”, not “same”

„Fotelik samochodowy” scores 0.872 against a true match at 0.922 (mmlw). This is why the tier has no bell and MATCH stays lexical.

High

Thresholds outweigh model size

Positive and hard-negative means are about 0.016 apart. The prefix mode moves AUC more than int8 does.

High

Timing is the risk, not compute

Vector search adds about 0.5 s per capped run. A late vector is missed silently.

High

Visibility comes free

Reuse the one SQL fragment plus visible_matches; vectors never leave the DB.

Medium-high

Bielik's base minimises novelty

Same export, tokenizer family and CPU profile as the model already running.

High

Parity gate is mandatory

granite collapsed under int8 (every cosine 0.999); mmlw keeps a min cosine of 0.9925.

SWOT

Strengths

Fits the existing contract, the ONNX path and the visibility rule; exact and filter-correct; small RAM and CPU cost; no new matcher dependency.

Weaknesses

Hard negatives poorly separated; narrow score bands; no real-name benchmark; synchronous writes add request latency.

Opportunities

The same sample tunes the lexical gate; int8 Bielik frees RAM; a path to search-page semantic search; VPS B escalation for bigger models.

Threats

Unknown VPS A capacity; tier name confusion; a one-way image switch; a future HNSW added carelessly.

Gaps and uncertainties
  • VPS A hardware is undocumented, and nothing was measured on it.
  • No real-name quality data; the probe has 41 positives (AUC SE about ±0.03–0.05).
  • pgvector timings use random vectors (valid for timing; HNSW recall is not representative).
  • The semantic SQL has not been run on the real 0099 schema.
  • Old-image compatibility after 0101 is inferred.
  • No source gives a description vs name ablation for short queries.
  • The backfill re-entry side effect is inferred.
