### Tech Stack (`project/tech-stack.md`)
Python 3.12+, FastAPI, SQLAlchemy 2.0 (async) + asyncpg, Alembic, PostgreSQL, uv, PyJWT (`pyjwt[crypto]`: `cryptography` for Google's RS256 ID tokens; `httpx` at runtime for the JWKS fetch), bcrypt, Pydantic v2, tenacity, ruff, mypy. Wants matcher `src/matcher` (aj-matcher): Python 3.12, asyncpg-only runtime, own `pyproject.toml`/`uv.lock`/`Dockerfile`, pytest + testcontainers, ruff, mypy strict. Database image `pgvector/pgvector:0.8.7-pg18-trixie` (compose and both test suites; pgvector `halfvec`, exact scan, no index) and the baked-in `sdadas/mmlw-roberta-base` int8 ONNX embedder (pinned revision, `/models/embed`, MatMul-only QInt8 behind a ≥ 0.99 parity gate in the Dockerfile `models` stage; onnxruntime/tokenizers serve it too). ## Technical Standards

### Global Standards

Located in `.maister/docs/standards/global/`

#### Error Handling (`standards/global/error-handling.md`)
Clear user messages, fail-fast validation, typed exceptions, centralized handling, and graceful degradation; deadlocks (`40P01`) and serialization failures (`40001`) as retryable conflicts — the shared 409 via rollback + `StaleDataError` in user-facing writes (`57014` stays 503, other DB errors propagate), one WARNING and retry on the next run in scheduled jobs, other job failures logged once with their traceback and not re-raised, so loops keep running (`app/wants/application/writes.py`, `src/matcher/matcher/db.py::log_failure`); the shared user-facing mapper is `app/db.py::mapped_transaction_conflicts` (wants writes, points confirm/attendance/config).

#### Validation (`standards/global/validation.md`)
Server-side validation, client-side feedback, early input checking, specific error messages, allowlists over blocklists, and integer inputs as `type="text" inputMode="numeric" pattern="[0-9]*"` (never `type=number`) with the raw string in state, one shared parser returning `null`/number/`undefined` (`parseCapacity` in `utils/appHelpers.ts`), an inline Polish `role="alert"` error with `aria-invalid`/`aria-describedby`, submit disabled while invalid, and server-side `ge`/`le` still enforced.

#### Development Conventions (`standards/global/conventions.md`)
Predictable file structure, up-to-date documentation, clean version control, environment variables, and minimal dependencies.

#### Coding Style (`standards/global/coding-style.md`)
Naming consistency, automatic formatting, descriptive names, focused functions, and uniform indentation.

#### Commenting (`standards/global/commenting.md`)
Let code speak through structure and naming, comment sparingly for non-obvious logic, avoid change-log comments.

#### Minimal Implementation (`standards/global/minimal-implementation.md`)
Build only what is needed, clear purpose for every method, delete exploration artifacts, no future stubs or speculative abstractions.

### Backend Standards

Located in `.maister/docs/standards/backend/`

#### API Design (`standards/backend/api.md`)
RESTful principles, consistent naming, versioning, plural nouns for resources, and limited nesting.

#### SQLAlchemy Entity Modeling (`standards/backend/models.md`)
SQLAlchemy 2.0 entity modeling standards: shared `BaseEntity` mixin (`app/core/base_model.py`) with a UUID `id` (`uuid4` default + `gen_random_uuid()` server default; no per-table `Sequence`), `created_at`, and `updated_at` doubling as `version_id_col` for optimistic locking; PK carve-outs (`PluginDescriptor` string PK, `RegisteredClient` app-generated UUID PK, the seeded `Locality` SIMC `String(7)`/`LocalityPostalCode` composite natural PKs, all on plain `Base`); required same-module relationships kept `lazy="raise"` behind module loaders (`Location.locality` only via `load_location`/`load_locations_by_ids` with `joinedload` + `populate_existing`, reloaded after create/update, the ACLs delegating to them, since `Location.label` reads it); string-backed enums; `lazy="raise"` plus explicit eager loading; business-key `__eq__`/`__hash__`; cross-module references as plain FK-id columns, with the groups BC declaring no `relationship()` at all and loading related rows via batched `IN` lookups; coordinates as `Numeric(9,6)` exposed as `float`; money as `Numeric(10,2)` kept a `Decimal` end to end — a decimal string such as `"25.50"` on the wire, `string` on the frontend, never a float, NULL (with a `> 0` CHECK) for none, a `mode="before"` cent-quantizing validator (`Term.price`, `groups/schemas.py::_validate_price`); soft delete via nullable naive-UTC `deleted_at` with explicit list filters and partial unique indexes (soft-deleted Circles 404 by id, referenced Locations still render with `deleted_at`/"(usunięte)"); the category tree (`parent_id` self-FK RESTRICT without `relationship()`, nullable unique Vinted `external_id`, `(parent_id, name)` uniqueness + partial root-unique index and business key, leaf-only products via `require_leaf_category`) and `inventory_items.listing_status` (DRAFT/ACTIVE, VARCHAR(20) via `_enum_column`, written only in lockstep with `item_listing_preferences`, by groups through `inventory_bridge`); and cross-context access through a single `infrastructure/<other>_acl.py` (no `..schemas` import, owner's 404-before-403 check, batched `get_<x>s_by_ids`, narrow `LocationRefResponse`/`PublicLocationResponse` embeds, unchanged reference ids not re-validated); and listing visibility safe by default (listing-preference selects PUBLIC-only via `include_private=False`, PRIVATE inclusion an explicit opt-in, private circles via `private_circle_id=` admitting a PRIVATE item only when its owner is a standing member or current organizer — RSVP never counts — in listings, browse, `/actions`, take/propose and `exchange_summary`; every item path through `item_visibility.can_view_item`/`require_item_visible` first so hidden items 404 before 403/409; `repository.py::_visible_preferences`/`_owner_in_circle`).

#### Database Queries (`standards/backend/queries.md`)
Parameterized queries via SQLAlchemy binding, N+1 avoidance with explicit eager loading (required, not optional, under `AsyncSession`), select only needed columns, strategic indexing via Alembic, and transactions; recursive CTE members built with `join_from(...)`/`.join(...)`, never a comma FROM + WHERE (FROM-linter cartesian-product `SAWarning`), pinned by a compile-with-`linting` test under `simplefilter("error", SAWarning)`; transaction-scoped statement timeouts (`SET LOCAL` in `app/search`, `limit_transaction` in `src/matcher`).

#### SQLAlchemy Core Query Standards (`standards/backend/jooq.md`)
SQLAlchemy Core dynamic-query standards for the two hand-rolled filter-DSL query services (`app/product/query_service.py`'s 4-part grammar, `app/plugin/query_service.py`'s 3-part grammar — deliberately kept separate, not unified): bind-parameter discipline for comparison values, regex-validate-then-splice for JSONB path segments (`IDENTIFIER_PATTERN`), the `exists` operator's bind-not-splice asymmetry, N+1 prevention, query optimization (EXISTS over COUNT, explicit ordering, enforced SQL-level LIMIT), and common pitfalls (no unvalidated splicing, no NOT IN with nullables, no incidental DISTINCT). Migrated from jOOQ.

#### Database Migrations (`standards/backend/migrations.md`)
Alembic workflow (`revision --autogenerate`, review before applying), reversible migrations whose `downgrade()` drops in reverse dependency order (FKs before columns, indexes before tables, later revisions before earlier ones), guarded downgrades allowed when ledger-linked rows would make them lossy (refuse with an error naming the recovery path, runbook in `architecture.md`; `0073_event_reservations.py`, `0074` open no-context reservations, `0075` same guard then loses pickup places, `0076` PRIVATE listings; operators run every guard count before any downgrade or image-only rollback), `SET LOCAL lock_timeout = '5s'` in lock-taking revisions (0073–0076, 0080), concurrent index builds inside `autocommit_block()` (0053, 0077), a downgrade-then-upgrade-head pytest per migration (`tests/test_locations_migration.py`, `tests/test_group_soft_delete_migration.py`), small focused changes (one-time full-schema `0001` exception), UUID PKs with `server_default=gen_random_uuid()` and `pk_<table>` (no sequences/IDENTITY), explicit `pk_`/`fk_<table>_<col>_<ref>`/`ix_`/`uq_` names, partial unique indexes via `postgresql_where=... AND deleted_at IS NULL`, additive nullable columns with no backfill in a separate revision from new tables, deleting self-referential trees leaves-first (repeat `DELETE … WHERE NOT EXISTS (child)`, never null `parent_id` first because nulled siblings collide on the partial root-unique index; `0069_vinted_categories.py`), reference data seeded from gzipped CSV fixtures in `alembic/data/` with a sources/licence/hashes/rebuild README, schema revision separate from the seed revision, validate-everything-before-insert, 10k-row chunked `INSERT … SELECT * FROM unnest(CAST(:col AS text[]), …)` (never `::text[]` in `sa.text`, it clashes with bind parsing; COPY not needed) and a `TRUNCATE` downgrade, refreshed by a new data revision (`0078_localities.py`, `0079_seed_localities.py`), data migrations deleting storage-backed rows staging `storage.objects_delete` outbox entries (`{"keys": [...]}` as in `_stage_photo_files_delete`, ≤1000 keys each) in the same transaction before the delete, zero-downtime awareness, separate schema and data migrations, and careful indexing. Migrated from Liquibase.

#### Security (`standards/backend/security.md`)
FastAPI dependency-based authorization (`Depends(require_any(...))`) replacing `@PreAuthorize`/`SecurityFilterChain`, the `AUTHORIZATION_MATRIX` reference table in `app/core/authorization_matrix.py` (first-match-wins evaluation order, verified by tests, enforced per route through `Depends(require_any(...))` or no dependency for PUBLIC rows), custom exception handlers replicating legacy 401/403 envelopes, PyJWT claim shapes (login token: `sub`/`permissions`/`iat`/`exp`; OAuth2-issued token: `iss`/`sub`/`scopes`/`iat`/`exp`/`aud`), bcrypt password hashing, and the preserved hand-rolled OAuth2 authorization server (PKCE, rotating refresh tokens, RFC 8693 token-exchange bridge) with its documented known gaps, token sources in order (Bearer header, `_token` form/query for the OAuth2 authorize POST, then the JS-readable `auth_token` cookie on GET/HEAD only via `_COOKIE_METHODS` in `app/core/_auth/token.py`, so mutations and plugins stay on Bearer and GETs stay side-effect free), auth-flow cookies (the backend's own `aj_google_nonce`: HttpOnly, SameSite=Lax, `Path=/api/auth/google`, Max-Age 600, `Secure` from `AUTH_COOKIE_SECURE` never from headers, an HS256 JWT under a purpose key derived from `JWT_SECRET`, set only by a JSON-body PUBLIC POST and cleared with the same attributes; PUBLIC POST rows 72/73 outside `/api/public/` as the auth-flow exception), Google ID tokens verified locally (RS256 + JWKS, `iss`/`aud`/`azp`/nonce via `compare_digest`, strict `email_verified`, no auto-linking by email: 409/403), nullable `password_hash` answering the ordinary login 401, and personalised public responses kept out of shared caches (`set_personalised_cache_headers(response, principal)` after a successful service call: `private, no-store` for a resolved principal, `public, max-age=0, s-maxage=60` for anonymous/invalid tokens, always `Vary: Authorization, Cookie`; used by item actions/details, event page, public circle access, organizer/owner-items routes and `GET /api/public/search`), and `GET /api/categories(/.*)?` as the one PUBLIC read outside `/api/public/` (matrix row 55, writes ADMIN in row 56). Migrated from Spring Security.

#### Plugin Authentication (`standards/backend/plugin-auth.md`)
Browser SDK auth via hostApp.getToken() and postMessage (the Next.js host serves `/assets/plugin-sdk.js` and `/assets/plugin-ui.css` on port 5173 and reads the token from localStorage via `auth/session.ts`; contract unchanged by the backend and frontend migrations), Bearer-only plugin calls (the host cookie counts on GET/HEAD only), server-side auth with createServerSDK now forwarding JWT to the FastAPI backend, and permission checking in plugins by decoding the JWT's flat `permissions`/`scopes` claim (client-side contract unchanged; server-side implementation notes updated for FastAPI).

#### Domain Clock (`standards/backend/time.md`)
Europe/Warsaw domain clock: `Term.occurs_on` is naive Warsaw wall-clock while audit timestamps (`created_at`, `updated_at`, `read_at`, `withdrawn_at`, `deleted_at`, markers) stay naive UTC via `datetime.utcnow()`; read "now" only via `from app.core import clock` + `clock.local_now()` (never `datetime.now()`/`date.today()`, module-attribute call so it can be patched; enforced by `tests/test_domain_clock_guard.py` for `app/groups/application`, `app/groups/router`, `app/events`, `app/pages`, `app/search` and `app/wants`; in `src/matcher` only `matcher/clock.py` reads the clock, naive UTC, `tests/test_clock_guard.py`); `tzdata` as a runtime dependency with fail-fast `clock.check_timezone()` first in the lifespan and `uv.lock` shipped with dependency changes; opt-in `freeze_local_now` fixture from `tests/conftest.py` (no freezegun/time-machine, Term times built from `clock.local_now()`); user-facing dates via `clock.format_term_day`/`clock.format_term_when` and notification text capped with `clock.fit_notification_message` (500 chars).
