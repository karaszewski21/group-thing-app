## Technical Standards

### Global Standards

Located in `.maister/docs/standards/global/`

#### Error Handling (`standards/global/error-handling.md`)
Clear user messages, fail-fast validation, typed exceptions, centralized handling, and graceful degradation.

#### Validation (`standards/global/validation.md`)
Server-side validation, client-side feedback, early input checking, specific error messages, allowlists over blocklists, and integer inputs as `type="text" inputMode="numeric" pattern="[0-9]*"` (never `type=number`) with the raw string in state, one shared parser returning `null`/number/`undefined` (`parseCapacity` in `utils/appHelpers.ts`), an inline Polish `role="alert"` error with `aria-invalid`/`aria-describedby`, submit disabled while invalid, and server-side `ge`/`le` still enforced.

#### Development Conventions (`standards/global/conventions.md`)
Predictable file structure, up-to-date documentation, clean version control, environment variables, and minimal dependencies.

#### Coding Style (`standards/global/coding-style.md`)
Naming consistency, automatic formatting, descriptive names, focused functions, and uniform indentation.

#### Commenting (`standards/global/commenting.md`)
Let code speak through structure and naming, comment sparingly for non-obvious logic, avoid change-log comments.

#### Minimal Implementation (`standards/global/minimal-implementation.md`)
Build only what is needed, clear purpose for every method, delete exploration artifacts, no future stubs or speculative abstractions.

### Backend Standards

Located in `.maister/docs/standards/backend/`

#### API Design (`standards/backend/api.md`)
RESTful principles, consistent naming, versioning, plural nouns for resources, and limited nesting.

#### SQLAlchemy Entity Modeling (`standards/backend/models.md`)
SQLAlchemy 2.0 entity modeling standards: shared `BaseEntity` mixin (`app/core/base_model.py`) with a UUID `id` (`uuid4` default + `gen_random_uuid()` server default; no per-table `Sequence`), `created_at`, and `updated_at` doubling as `version_id_col` for optimistic locking; PK carve-outs (`PluginDescriptor` string PK, `RegisteredClient` app-generated UUID PK, the seeded `Locality` SIMC `String(7)`/`LocalityPostalCode` composite natural PKs, all on plain `Base`); required same-module relationships kept `lazy="raise"` behind module loaders (`Location.locality` only via `load_location`/`load_locations_by_ids` with `joinedload` + `populate_existing`, reloaded after create/update, the ACLs delegating to them, since `Location.label` reads it); string-backed enums; `lazy="raise"` plus explicit eager loading; business-key `__eq__`/`__hash__`; cross-module references as plain FK-id columns, with the groups BC declaring no `relationship()` at all and loading related rows via batched `IN` lookups; coordinates as `Numeric(9,6)` exposed as `float`; soft delete via nullable naive-UTC `deleted_at` with explicit list filters and partial unique indexes (soft-deleted Circles 404 by id, referenced Locations still render with `deleted_at`/"(usunięte)"); the category tree (`parent_id` self-FK RESTRICT without `relationship()`, nullable unique Vinted `external_id`, `(parent_id, name)` uniqueness + partial root-unique index and business key, leaf-only products via `require_leaf_category`) and `inventory_items.listing_status` (DRAFT/ACTIVE, VARCHAR(20) via `_enum_column`, written only in lockstep with `item_listing_preferences`, by groups through `inventory_bridge`); and cross-context access through a single `infrastructure/<other>_acl.py` (no `..schemas` import, owner's 404-before-403 check, batched `get_<x>s_by_ids`, narrow `LocationRefResponse`/`PublicLocationResponse` embeds, unchanged reference ids not re-validated); and listing visibility safe by default (listing-preference selects PUBLIC-only via `include_private=False`, PRIVATE inclusion an explicit opt-in, private circles via `private_circle_id=` admitting a PRIVATE item only when its owner is a standing member or current organizer — RSVP never counts — in listings, browse, `/actions`, take/propose and `exchange_summary`; every item path through `item_visibility.can_view_item`/`require_item_visible` first so hidden items 404 before 403/409; `repository.py::_visible_preferences`/`_owner_in_circle`).

#### Database Queries (`standards/backend/queries.md`)
Parameterized queries via SQLAlchemy binding, N+1 avoidance with explicit eager loading (required, not optional, under `AsyncSession`), select only needed columns, strategic indexing via Alembic, and transactions.

#### SQLAlchemy Core Query Standards (`standards/backend/jooq.md`)
SQLAlchemy Core dynamic-query standards for the two hand-rolled filter-DSL query services (`app/product/query_service.py`'s 4-part grammar, `app/plugin/query_service.py`'s 3-part grammar — deliberately kept separate, not unified): bind-parameter discipline for comparison values, regex-validate-then-splice for JSONB path segments (`IDENTIFIER_PATTERN`), the `exists` operator's bind-not-splice asymmetry, N+1 prevention, query optimization (EXISTS over COUNT, explicit ordering, enforced SQL-level LIMIT), and common pitfalls (no unvalidated splicing, no NOT IN with nullables, no incidental DISTINCT). Migrated from jOOQ.

#### Database Migrations (`standards/backend/migrations.md`)
Alembic workflow (`revision --autogenerate`, review before applying), reversible migrations whose `downgrade()` drops in reverse dependency order (FKs before columns, indexes before tables, later revisions before earlier ones), guarded downgrades allowed when ledger-linked rows would make them lossy (refuse with an error naming the recovery path, runbook in `architecture.md`; `0073_event_reservations.py`, `0074` open no-context reservations, `0075` same guard then loses pickup places, `0076` PRIVATE listings; operators run every guard count before any downgrade or image-only rollback), `SET LOCAL lock_timeout = '5s'` in lock-taking revisions (0073–0076, 0080), concurrent index builds inside `autocommit_block()` (0053, 0077), a downgrade-then-upgrade-head pytest per migration (`tests/test_locations_migration.py`, `tests/test_group_soft_delete_migration.py`), small focused changes (one-time full-schema `0001` exception), UUID PKs with `server_default=gen_random_uuid()` and `pk_<table>` (no sequences/IDENTITY), explicit `pk_`/`fk_<table>_<col>_<ref>`/`ix_`/`uq_` names, partial unique indexes via `postgresql_where=... AND deleted_at IS NULL`, additive nullable columns with no backfill in a separate revision from new tables, deleting self-referential trees leaves-first (repeat `DELETE … WHERE NOT EXISTS (child)`, never null `parent_id` first because nulled siblings collide on the partial root-unique index; `0069_vinted_categories.py`), reference data seeded from gzipped CSV fixtures in `alembic/data/` with a sources/licence/hashes/rebuild README, schema revision separate from the seed revision, validate-everything-before-insert, 10k-row chunked `INSERT … SELECT * FROM unnest(CAST(:col AS text[]), …)` (never `::text[]` in `sa.text`, it clashes with bind parsing; COPY not needed) and a `TRUNCATE` downgrade, refreshed by a new data revision (`0078_localities.py`, `0079_seed_localities.py`), data migrations deleting storage-backed rows staging `storage.objects_delete` outbox entries (`{"keys": [...]}` as in `_stage_photo_files_delete`, ≤1000 keys each) in the same transaction before the delete, zero-downtime awareness, separate schema and data migrations, and careful indexing. Migrated from Liquibase.

#### Security (`standards/backend/security.md`)
FastAPI dependency-based authorization (`Depends(require_any(...))`) replacing `@PreAuthorize`/`SecurityFilterChain`, the `AUTHORIZATION_MATRIX` reference table in `app/core/authorization_matrix.py` (first-match-wins evaluation order, verified by tests, enforced per route through `Depends(require_any(...))` or no dependency for PUBLIC rows), custom exception handlers replicating legacy 401/403 envelopes, PyJWT claim shapes (login token: `sub`/`permissions`/`iat`/`exp`; OAuth2-issued token: `iss`/`sub`/`scopes`/`iat`/`exp`/`aud`), bcrypt password hashing, and the preserved hand-rolled OAuth2 authorization server (PKCE, rotating refresh tokens, RFC 8693 token-exchange bridge) with its documented known gaps, token sources in order (Bearer header, `_token` form/query for the OAuth2 authorize POST, then the JS-readable `auth_token` cookie on GET/HEAD only via `_COOKIE_METHODS` in `app/core/_auth/token.py`, so mutations and plugins stay on Bearer and GETs stay side-effect free), and personalised public responses kept out of shared caches (`set_personalised_cache_headers(response, principal)` after a successful service call: `private, no-store` for a resolved principal, `public, max-age=0, s-maxage=60` for anonymous/invalid tokens, always `Vary: Authorization, Cookie`; used by item actions/details, event page, public circle access, organizer/owner-items routes and `GET /api/public/search`), and `GET /api/categories(/.*)?` as the one PUBLIC read outside `/api/public/` (matrix row 55, writes ADMIN in row 56). Migrated from Spring Security.

#### Plugin Authentication (`standards/backend/plugin-auth.md`)
Browser SDK auth via hostApp.getToken() and postMessage (the Next.js host serves `/assets/plugin-sdk.js` and `/assets/plugin-ui.css` on port 5173 and reads the token from localStorage via `auth/session.ts`; contract unchanged by the backend and frontend migrations), Bearer-only plugin calls (the host cookie counts on GET/HEAD only), server-side auth with createServerSDK now forwarding JWT to the FastAPI backend, and permission checking in plugins by decoding the JWT's flat `permissions`/`scopes` claim (client-side contract unchanged; server-side implementation notes updated for FastAPI).

#### Domain Clock (`standards/backend/time.md`)
Europe/Warsaw domain clock: `Term.occurs_on` is naive Warsaw wall-clock while audit timestamps (`created_at`, `updated_at`, `read_at`, `withdrawn_at`, `deleted_at`, markers) stay naive UTC via `datetime.utcnow()`; read "now" only via `from app.core import clock` + `clock.local_now()` (never `datetime.now()`/`date.today()`, module-attribute call so it can be patched; enforced by `tests/test_domain_clock_guard.py` for `app/groups/application`, `app/groups/router`, `app/events` and `app/pages`); `tzdata` as a runtime dependency with fail-fast `clock.check_timezone()` first in the lifespan and `uv.lock` shipped with dependency changes; opt-in `freeze_local_now` fixture from `tests/conftest.py` (no freezegun/time-machine, Term times built from `clock.local_now()`); user-facing dates via `clock.format_term_day`/`clock.format_term_when` and notification text capped with `clock.fit_notification_message` (500 chars).

TanStack Query v5 hooks in `src/hooks/` wrapping `src/api/*.ts` (no `useState`+`useEffect` fetching, no ad hoc `useQuery` in components), one QueryClient from `getQueryClient()` in `src/api/queryClient.ts` (browser singleton, new per server render), provided in `src/app/providers.tsx` (no retry on `ApiError` 4xx, up to 2 retries on network/5xx), server-side reads only through `src/api/server.ts` (`server-only`, anonymous, `cache: "no-store"`, React `cache()` per request, `null` on failure, named loaders, metadata and initial palette only), array query keys with a resource-name prefix constant followed by params, mutations that `await invalidateQueries` on the whole resource prefix and pass `extractProblemMessage` errors through verbatim, app-shaped hook returns (`data` with a stable module-level empty fallback, `loading = isPending`, `error: string | null`, `refetch(): Promise<void>`), keeping values such as the auth token out of the key when shown data must survive their change (`useTermAccess` `forToken`/`isStale` pattern), passing a host hook's mutation callbacks (`create`/`update`/`remove`) down as props instead of re-subscribing in a child (a second `staleTime: 0` subscriber refetches on every mount; `LocationAddForm`'s `create` prop), the documented `staleTime` exception for `useCategories` (5 min for the ~2300-node tree, so every category/product-count write awaits invalidation of the categories prefix: `useCategories` create/update/remove/move, `useProducts` invalidate, admin `ProductFormPage` after save), and dates via `dayjs` imported from `src/utils/dayjs.ts` (Polish `pl` locale; never import `"dayjs"` directly; `src/utils/format.ts` is legacy).
